# M3 — History and research Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** General diagnostics over history — keep a searchable record of notable and hourly processes plus every distinct command line, with tags, so `/analytics`, `/commands`, and CLI `history`/`commands search`/`reclassify` can answer behavior and capacity questions without ad-hoc SQL.

**Architecture:** Collector classifies → tags → emits `process_samples` + `command_lines` sightings; `DatabaseWriter` upserts them (daily partitions for samples, hash-keyed upsert for cmdlines); `FastAPI` serves SQL-side roll-ups for `/analytics` (trends, agent adoption, dormancy, leaderboards) and trigram-assisted search for `/commands`.

**Tech Stack:** Python ≥3.10, psycopg 3, Postgres 18 (existing `node_monitor` DB), FastAPI + Vue 3 + Chart.js vendored (no CDN), pytest/httpx, ruff.

**Spec:** `docs/superpowers/specs/2026-11-09-m3-history-design.md` + `docs/superpowers/specs/2026-10-28-node-monitor-v2-design.md` §6 data model, §7 web (analytics/commands rows), §13 M3.

## Global Constraints

- Repo `~/node-monitor/node-monitor`, branch `feat/m3-history` from `main`, venv `~/node-monitor/venv` editable, live commands `env -u LD_PRELOAD`.
- 3-space indent, `ruff check . && ruff format --check .` must pass, `docs/` never formatted, Python ≥3.10, no `asyncio.wait_for`.
- `node-monitor history|commands search|reclassify` read via `web.database_url` (or `database.url` for reclassify writes), one-line ClickException on missing URL, never traceback.
- Postgres tests use `migrated_db`/`pg_db` fixtures (skip unless `NODE_MONITOR_TEST_ADMIN_URL` set, only `node_monitor_test_*`); API tests via `httpx` never touch real `node_monitor` DB.
- No CDN — reuse `node_monitor/web/static/vendor/vue.global.prod.js@3.4.38` + `chart.umd.min.js@4.4.9`.
- Every visible cmdline is redacted; tags are `text[]`; missing user/cmdline → 404 with allowed-values hint, not empty.

## Review Focus

- A 30-day `process_samples` range (20M rows) is requested — API must page/cap, not dump all rows.
- A new flag `--dangerously-skip-permissions` appears — tag table must pick it up without code change, and old rows must be reclassifiable.
- A cmdline contains `%`, `_`, or regex metachars — search must treat substring vs regex distinctly and never allow ReDoS.
- A user has 100k distinct cmdlines — `/commands` must page and not freeze.
- Retention boundary: a `process_samples` partition at exactly 30d old must be dropped, and a `command_lines` row with `last_seen == now-730d` must be kept (strict >).

Each gets a test in its owning task (see Task steps).
