# M2 — Live web dashboard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A live web dashboard that shows whether the collector and login nodes are healthy and what users are doing right now, with drill-downs to a node and to a user.

**Architecture:** FastAPI serves JSON under `/api/...` from the read-only role and static Vue 3 pages. Pages poll every 30 s (an explicit disconnected banner on failure) and reuse the same DB queries the CLI already uses, plus historical roll-ups against `node_metrics_1m`/`*_usage_5m`. The primary page's process-dot canvas is a plain `<canvas>` component driven by the live-process API — no extra backend.

**Tech Stack:** FastAPI + uvicorn, Vue 3 + Chart.js vendored at pinned versions under `node_monitor/web/static/vendor/`, psycopg 3, pytest + httpx, ruff.

**Spec:** `docs/superpowers/specs/2026-10-28-node-monitor-v2-design.md` §7 (first three rows + process modal), §3 repo layout, §6 data model where it touches live/history tables.

**Inputs:** M1c live tables (`live_processes`, `live_nodes`, `live_snapshots`, `nodes`, `collector_heartbeat`), history tables, `node_monitor/database/queries.py`, `docs/m1c-week.md`.

## Global Constraints

- Repo `~/node-monitor/node-monitor`, branch `feat/m2-live-web` from `main`, venv `~/node-monitor/venv` editable, live commands with `env -u LD_PRELOAD`.
- 3-space indentation, `ruff check . && ruff format --check .` must pass, `docs/` never formatted, Python ≥3.10, no `asyncio.wait_for`.
- `node-monitor web [--host 127.0.0.1 --port 9998 --config PATH]` — loopback by default, read via `web.database_url`, exits 1 with one line if the URL is missing, never prints a traceback.
- Tests that hit Postgres use `migrated_db`/`pg_db` fixtures (skip unless `NODE_MONITOR_TEST_ADMIN_URL` set, only `node_monitor_test_*` DBs); API tests use `httpx`/`TestClient`, never the real `node_monitor` DB.
- No CDN: vendor Vue and Chart.js under `node_monitor/web/static/vendor/` at pinned versions (record exact versions in the commit).
- Every visible command line is the redacted one; a missing user/process shows a clear 404, not an empty page.

## Review Focus

1. A login node goes dark (session `down` or heartbeat stale) — the health strip must say which node and since when, not just "degraded".
2. A user with 2k live processes opens `/user/{name}` — the page must page or cap the list, not freeze the browser.
3. A 2-year range is requested on `/node/{node}` (tens of thousands of 1m rows) — the API must return hourly/daily roll-ups, not the raw rows, or the tab will OOM.
4. The web process has no DB — startup must fail fast with a readable error, and polling pages must show "web server disconnected" rather than stale zeros.
5. A process cmdline contains `[bold]` or an ANSI escape — the UI must render it as literal text, not styled markup or a terminal injection.

Each is pinned by a test in its owning task (see Task steps).
